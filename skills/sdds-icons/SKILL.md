# Работа с SDDS Icons

Использовать этот skill, чтобы выбрать реально существующую иконку, корректный размер и публичный импорт из `@salutejs/sdds-icons`. Не придумывать имена компонентов по памяти.

## Источники истины

1. Для подбора иконки использовать MCP tool `search_icons` из `sdds-mcp`.
2. Для совместимости с конкретным проектом проверить установленную версию `@salutejs/sdds-icons`, локальные импорты и результат typecheck.
3. Если результат MCP расходится с экспортами установленной версии, использовать API установленного пакета либо согласовать его обновление. Не подменять отсутствующую иконку выдуманным именем.

Если `search_icons` недоступен, искать только по локальным экспортам установленного пакета или его документации и явно отметить ограничение. Не угадывать имя иконки.

## Поиск и выбор

1. Определить смысл иконки из задачи, подписи элемента, действия пользователя, контекста интерфейса или Figma-макета. Не выбирать только по визуальному сходству.
2. Вызвать `search_icons` с коротким смысловым запросом. Запрос может состоять из одного слова или фразы. Обычно достаточно `limit` от 5 до 10.
3. Оценить `name`, `category`, `aliases` и `sizes` каждого результата. Порядок отражает поисковую релевантность, но первый результат не обязан быть правильным по смыслу интерфейса.
4. Если подходящего результата нет, сделать не более двух дополнительных запросов, меняя формулировку по существу:
    - оставить ключевое действие или объект;
    - попробовать близкую русскую или английскую формулировку;
    - убрать слова, относящиеся к конкретному экрану, но не к значению иконки.
5. Учитывать варианты в имени (`Outline`, `Fill`, `Bold` и другие) и выбирать вариант, соответствующий макету и соседним иконкам.
6. Если несколько вариантов одинаково уместны и выбор заметно меняет смысл или вид интерфейса, показать пользователю 2–3 кандидата. В остальных случаях выбрать наиболее обоснованный вариант и кратко зафиксировать допущение.

## Выбор размера

- Использовать только размер из `sizes`, возвращенных для выбранной иконки.
- Если размер задан пользователем, макетом или API компонента, использовать его.
- Иначе ориентироваться на уже используемый размер в том же компоненте или соседних элементах интерфейса.
- Размер в пути импорта должен совпадать с выбранным вариантом: `16`, `24` или `36`.
- Не импортировать иконку из одного размера с последующим масштабированием под другой, если нужный размер доступен отдельной точкой входа.

## Статическое использование

Если имя известно во время сборки, использовать статический импорт. Следовать принятому в проекте стилю; обычный именованный импорт выглядит так:

```tsx
import { ArrowBackOutline } from '@salutejs/sdds-icons/24';

export const BackAction = () => <ArrowBackOutline aria-hidden />;
```

У пакета нет корневого экспорта: импорт из `@salutejs/sdds-icons` без размера некорректен.

Допустим прямой импорт конкретного компонента, если такой стиль уже используется в проекте или важно уменьшить объем обрабатываемого сборщиком общего entry point:

```tsx
import ArrowBackOutline from '@salutejs/sdds-icons/24/ArrowBackOutline';
```

Иконки наследуют цвет через `currentColor`. Не добавлять `color="inherit"`. Для изменения цвета использовать существующие токены или стили проекта; `color`, `width`, `height`, `className` и другие стандартные SVG-свойства передавать только когда это требуется интерфейсом.

## Динамическое использование

Использовать `DynamicIcon` только когда имя приходит во время выполнения, например из CMS или API. Для произвольной строки сначала вызвать `isIconName`:

```tsx
import { DynamicIcon, isIconName } from '@salutejs/sdds-icons/24/dynamic';

export const RuntimeIcon = ({ name }: { name: string }) =>
    isIconName(name) ? <DynamicIcon name={name} aria-hidden /> : null;
```

Не использовать динамический API для заранее известной иконки: статический импорт проще и не требует загрузки модуля иконки во время выполнения.

## Доступность

- Для декоративной иконки или иконки внутри элемента с понятной текстовой подписью использовать `aria-hidden`.
- Для самостоятельной смысловой иконки обеспечить доступное имя через подходящий паттерн проекта, например `aria-label`.
- Не полагаться на имя React-компонента как на доступное имя в интерфейсе.

## Проверка результата

Перед завершением убедиться, что:

- имя компонента присутствует в результатах `search_icons` или локальных экспортах установленной версии;
- выбранный размер присутствует в `sizes` и совпадает с путем импорта;
- пакет установлен в целевом проекте;
- в коде нет корневого импорта, выдуманного имени и лишнего `color="inherit"`;
- декоративность или смысл иконки отражены в accessibility-атрибутах;
- минимальный релевантный typecheck или сборка проходят успешно.

Если импорт не компилируется, проверить версию пакета и его реальные экспорты, затем повторить поиск. Не исправлять ошибку перебором предполагаемых имен.
